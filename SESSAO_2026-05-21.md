## 3. Multi-Processo: Carteira de Selos Gamificada

**Contexto:** um fornecedor pode participar de múltiplos processos de homologação simultaneamente (SIGEC próprio + um processo por cliente que o convidou). Era necessário:
- Criar o processo do cliente automaticamente quando o convite é aceito
- Redesenhar o dashboard do fornecedor para exibir todos os processos
- Criar página de detalhe por processo
- Componente visual reutilizável para o "Selo"

### 3.1 Banco de dados — trigger de auto-criação

**Arquivo criado:** `supabase/patch_016_process_seals.sql`

- Trigger `trg_auto_create_process_seal` dispara em `UPDATE` na tabela `invitations`
- Quando `status → 'REGISTERED'` e o convite tem `client_id` → insere automaticamente um registro em `seals` (status `PENDING`, level `Simples`)
- Backfill: insere seals para convites que já estavam em `REGISTERED` e ainda não tinham seal gerado
- `ON CONFLICT DO NOTHING` → idempotente

## 4. Categorias e Documentos — Atualização via CSV

**Contexto:** manter os códigos de categorias e documentos existentes enquanto se atualiza o conteúdo a partir de um CSV (`documentos e categorias elos.csv`). Cada cliente recebe uma cópia do fluxo padrão que pode customizar.

### 4.1 Script gerador

**Arquivo criado:** `scripts/generate-categories-sql.js`

- Script ES module que lê o CSV (`id_categoria;descricao_categoria;id_categoria_pai;id_documento;descricao_documento`)
- Desduplicação por ID inteiro
- Ordena categorias por ID crescente → garante que pais sejam inseridos antes dos filhos (FK auto-satisfeita)
- Gera `supabase/patch_017_categories.sql`

**Como executar:**
```bash
node scripts/generate-categories-sql.js
```

### 4.2 Patch SQL gerado

**Arquivo gerado:** `supabase/patch_017_categories.sql`  
**Resultado:** 1.429 categorias · 30 documentos · 14.508 vínculos categoria→documento

Tabelas criadas/populadas:
| Tabela | Descrição |
|--------|-----------|
| `categories` | Hierarquia de categorias com `parent_id` self-referencial |
| `documents_catalog` | Catálogo de 30 tipos de documentos |
| `category_documents` | Mapeamento padrão categoria → documento |
| `client_document_flows` | Cópia do padrão por cliente; `required=false` = removido; linha extra = adicionado |

- Seed automático ao final: copia `category_documents → client_document_flows` para todos os clientes existentes
- `ON CONFLICT DO NOTHING` em todos os INSERTs → idempotente (re-aplicável)
- RLS em todas as tabelas

**Contexto:** o backoffice é a única entidade que pode incluir/excluir documentos do fluxo de um cliente específico.

### 5.1 Tela nova

**Arquivo criado:** `src/pages/backoffice/ClientDocumentFlows.jsx`  
**Rota:** `/backoffice/fluxo-documentos`

**Funcionalidades:**
- Seletor de cliente
- 3 KPIs: documentos removidos / adicionados / categorias modificadas vs. padrão
- Campo de busca por nome de categoria (quando vazio, exibe só as categorias modificadas)
- Accordion por categoria com badge `modificado` e contagem `X/Y docs ativos`
- Dentro de cada categoria:
  - **Documentos Padrão** — checkboxes; desmarcar remove (sets `required=false`); remarcar restaura

- Salva individualmente a cada toggle (sem botão de salvar)
- Spinner por linha enquanto salva
